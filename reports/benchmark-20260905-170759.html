Method & caveats

Read the numbers above alongside these notes on how this benchmark was run.

  1. One trial per configuration. These are single runs, not averages across repeated trials; treat the curve as indicative, not a precise scaling law.
  2. Latency here means backlog-drain time, not live request latency. All 1000 messages for a run were published to data-changed before the subscriber connected, so p50/p99 mostly measure how long a message waited its turn in a full queue, not publish-to-handle time under steady, trickling traffic.
  3. Ordering. SolaceConcurrentSubscriber<T> was run with a key selector that routes same-OrderId messages to one lane, in delivery order. Zero ordering violations across all 5 runs (5000 messages) confirms that guarantee held.
  4. The simulated handler cost is what makes this comparison meaningful. SimulatedHandlerWorkMinMs/MaxMs (250–1000 ms, uniform random) stands in for real per-message work — an external call, a database write. Without it, both subscriber types process trivial work at roughly the same rate, since there's nothing for concurrency to overlap.

Addendum: n=32 lanes (this machine's CPU count)

Run separately, after the sweep above, at a different KeyCount and time — not a controlled comparison, so it's reported here rather than folded into the "Full results" table.

ConfigurationLanesMessagesKeysElapsed Throughputp50p99Violations
Concurrent 32 1000 64 40.82s 24.5/s 19478.7 ms 39861.4 ms 0

32 lanes matches this machine's logical CPU count. KeyCount was raised to 64 for this run (from 16 in the sweep above): with only 16 distinct keys, a key selector routing by hash to 32 lanes could never actually use more than 16 of them, since no single key is ever handled by more than one lane. At 64 keys (~2 per lane on average), all 32 lanes get real work.

For a rough sense of scale against the sweep above — read loosely, not as a like-for-like row, since KeyCount differs — 24.5 msgs/sec is roughly 15.3× the sequential baseline (1.6 msgs/sec) and about 4.7× the n=8 result (5.2 msgs/sec) from that run, for a 4× increase in lanes. Zero ordering violations, consistent with the sweep above.
