Global duplicates by WindowSize

No duplicates observed at any WindowSize in this sweep - either JoinDelaySeconds/Count/simulated work weren't aggressive enough to leave real backlog outstanding at handoff time, or the handoff genuinely completed cleanly every time. Try a larger -Count, a shorter -JoinDelaySeconds, or slower SimulatedHandlerWork*Ms in appsettings.json to manufacture more backlog.

Method & caveats

Read the numbers above alongside these notes on how this benchmark was run.

  1. One trial per WindowSize value. Rebalance timing races against real wall-clock delays (JoinDelaySeconds, the broker's own partitionRebalanceDelay/partitionRebalanceMaxHandoffTime), so a single run can land on either side of the timing window that produces a duplicate. Treat this as indicative, not a precise rate.
  2. Global vs. per-process counts measure different things. See the table caption above - only the global, cross-process merge can see a message the original consumer handled once and the post-handoff new owner handled again.
  3. This exercises the partial-rebalance path, not FlowActive/FlowInactive. Adding instances here causes each existing one to give up some (not all) of its partitions, which never fires Solace's FlowInactive event - see the script header for why, and what topology would be needed to exercise that path instead.
  4. Every instance is torn down with Stop-Job (a hard kill), including at the end of each configuration. The graceful drain-before-disconnect fix in SubscriberHostedService is not exercised by this sweep - it only matters for a real, signaled shutdown, which doesn't happen here.
  5. The simulated handler cost and JoinDelaySeconds are what make a handoff-time duplicate possible at all. If SimulatedHandlerWork*Ms in appsettings.json is fast enough (or JoinDelaySeconds long enough) that the initial instances fully drain before joiners even bind, there's nothing for the joiners to be handed off mid-flight and this sweep degenerates to run-benchmark-multisubscriber.ps1's startup-only case.
